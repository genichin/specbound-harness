# Micro-SPEC — REQ-0003 slice 006: failure-atomic fixture publication

> **Lifecycle boundary:** This artifact binds only AC-006 of exact approved `req-0003-r2`. Implementation requires its own exact digest-bound `approved_for_implementation` review decision. It grants no approval, adoption, implementation-completion, merge, delivery, or release authority.

## Objective

Make fixture-only publication failure-atomic: after exclusive creation, write, flush, file fsync, directory fsync, or post-write digest validation failures must leave no visible target owned by the failed publisher, while a competing winner remains untouched.

## Scope

- Write exact candidate bytes through the AC-005 exclusive-create descriptor.
- Flush and fsync the completed leaf, fsync its containing directory, and recompute the final leaf SHA-256 before reporting success.
- Retain inode/device identity for the leaf created by this operation.
- On controlled post-create failure, unlink only a target that still has the owned identity; never delete an existing/competing target.
- Add isolated fault injection for write, flush, file fsync, directory fsync, and post-write digest validation failures, including a competing-winner preservation case.

## Non-goals

- Overwrite, delete-and-retry, repair, or replacement of any pre-existing target.
- Recovery guarantees outside controlled same-host/local-filesystem fixture failures.
- AC-007 success-result digest/path contract, production adoption, live issuance, lifecycle authority, merge, delivery, or release.

## Baseline

AC-005 supplies canonical path traversal and exclusive creation. It may leave a partially written leaf on post-create failure; AC-006 narrowly replaces that failure behavior without changing prerequisite validation or publication authority.

## Verification plan

- Focused fault-injection tests assert no target remains after each owned failure.
- A simulated replacement/competing winner preserves the winner bytes during cleanup.
- Successful fixture publication fsyncs file/directory and recomputes exact final digest internally.
- Run focused/full pytest, preflight, validate, and `git diff --check`.

## QC exit rule

Every specified controlled failure reports failure with no failed-operation target visible; successful output remains limited to the requested copied-fixture leaf.

## Rollback and containment

Cleanup is identity-checked and can remove only the inode created by the failed operation. All failure injection is confined to isolated copied fixtures; canonical approved artifacts, adoption state, prior evidence, and production paths remain unchanged.
