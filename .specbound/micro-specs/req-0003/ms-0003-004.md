# Micro-SPEC — REQ-0003 slice 004: QC prerequisite policy

> **Lifecycle boundary:** 이 planning artifact는 exact approved `req-0003-r2`의 AC-004에만 binding된다. 이 문서와 이후 발급될 review-decision은 approval, adoption, implementation completion, merge, delivery 또는 release authority가 아니다. High-risk parent이므로 exact append-only `micro-spec review-decision`의 `approved_for_implementation` verdict가 있어야 이 bounded slice만 구현할 수 있다.

## Objective

AC-001~003의 issuance boundary 위에 copied fixture 전용 `iteration-qc` 및 `delivery-qc` issuance prerequisite policy를 구현한다. 요청 target을 publish하기 전에 exact approved REQ/approval binding, fixture-local applicable adoption evidence 및 complete canonical parent graph를 read-only로 resolve한다. 성공은 requested QC artifact 하나만 만들며 production adoption registry 또는 lifecycle claim을 만들지 않는다.

## Scope

- `iteration-qc`는 exact adopted Micro-SPEC parent, adopted REQ/approval binding 및 complete canonical parent graph가 valid할 때만 copied fixture에 요청 target 하나를 publish한다.
- `delivery-qc`는 referenced iteration-QC와 Micro-SPEC의 exact adopted edges 및 parent graph 전체가 valid할 때만 copied fixture에 요청 target 하나를 publish한다.
- missing, mismatched, stale, malformed, unsafe, semantically invalid, unapproved, unadopted 또는 approval-record-invalid parent/adoption data를 target mutation 전에 distinct structured blocker로 reject한다.
- pre-adoption production registry empty state를 유지하고, positive/negative regression fixture에서만 adoption input을 만든다.
- successful QC artifact/result/help/template은 approval, adoption, implementation completion, merge, delivery 또는 release authority를 주장하지 않는다.

## Non-goals

- production adoption registry 변경, live QC issuance, control-plane adoption implementation 또는 adopter-agent layout Discovery.
- atomic exclusive publication, competing writer handling, fsync/controlled cleanup 또는 final published digest result contract(AC-005~AC-007).
- approved REQ, approval, existing Micro-SPEC/review record 또는 production evidence rewrite.
- approval, adoption, implementation completion, merge, delivery 또는 release authority issuance.

## QC exit rule

Both copied-fixture valid QC family publications and every invalid parent/adoption rejection must pass; each success may change only its requested QC target and must retain non-authorizing wording. Only then may bounded iteration-QC be requested. This is not an AC-005~AC-008, adoption, implementation, merge, delivery, or release completion claim.

## Rollback and containment

If a QC target is created without its complete approved/adopted graph, if a parent/adoption record mutates, or if authority leaks, disable/reject the QC publish mode and retain fixture evidence. Any containment cleanup is limited to the requested target owned by the copied-fixture invocation; it must not alter production registry, approved REQ/approval, existing evidence, historical review records, or live Hermes profiles.
