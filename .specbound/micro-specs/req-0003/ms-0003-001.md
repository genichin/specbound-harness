# Micro-SPEC — REQ-0003 slice 001: explicit issuance request prevalidation

> **Lifecycle boundary:** 이 Micro-SPEC은 exact approved `req-0003-r1` snapshot의 AC-001 및 AC-002에만 binding된 planning artifact이다. approval, iteration-QC, delivery-QC, adoption, implementation 완료, merge, delivery 또는 release authority가 아니다. independent review 후에만 이 slice의 구현을 시작할 수 있다.

## Objective

하나의 artifact-kind-selected `specbound` CLI issuance request surface를 정의·구현하여 `micro-spec`, `iteration-qc`, `delivery-qc` kind 각각에 대해 explicit canonical target identity와 complete candidate-content input을 받는다. 파일시스템 mutation 전에 request shape, kind, canonical target/path/identity, candidate schema·semantic validity 및 family-specific parent-precondition dispatch를 fail-closed로 평가하고, rejection 시 structured machine-readable blocker와 target absence를 보장한다.

## Scope

- `src/specbound/cli.py`와 관련 validation/helper 경계에 하나의 명시적 issuance operation을 추가한다. operation은 kind selector, target identity, complete candidate-content input을 요구하며 implicit numbering, artifact scan, existing target inference를 하지 않는다.
- configured canonical form에 맞는 `micro-spec`, `iteration-qc`, `delivery-qc` kind와 safe repository-relative target identity만 dispatch한다. unknown kind, malformed/ambiguous target, absolute path, traversal, noncanonical alias 및 malformed/invalid content는 write attempt 전에 reject한다.
- candidate artifact의 schema 및 semantic validation, canonical target/identity binding, 그리고 kind별 parent-precondition validation을 write-capability와 분리된 pre-publication boundary로 설계·구현한다. 이 slice에서 adoption·parent-graph rule의 full family behavior는 후속 slice가 완성하지만, 현재 operation은 family-specific validation dispatch가 없는 request를 success로 취급하지 않는다.
- structured success/rejection result envelope의 kind, safe-relative path 또는 blocker code/path/detail contract를 문서화하고, all-prepublication rejection에 requested target이 absent임을 copied/temporary fixture에서 검증한다.
- repository-local CLI/help 및 authoring guidance를 이 narrow, non-authority request boundary와 일치시킨다.

## Non-goals

- canonical artifact publication, atomic exclusive create, duplicate/race behavior, fsync, ownership-safe cleanup, final digest reporting 또는 overwrite semantics는 AC-005~AC-007 후속 slice로 defer한다.
- valid planning-only pre-adoption Micro-SPEC issuance policy(AC-003), adopted iteration-QC/delivery-QC full parent graph policy(AC-004), exhaustive cross-family behavioral matrix(AC-008)를 완료하거나 claim하지 않는다.
- approval, confirmation, rejection, adoption, merge, delivery decision, release, live rollout, production `specbound.yaml` adoption registry 또는 existing/manual-bootstrap artifact를 변경하지 않는다.
- approved REQ 또는 approval record의 bytes를 변경하지 않는다.

## Baseline

`req-0003-r1`은 approval record `.specbound/approvals/req-0003-r1.approval.json`에 exact SHA-256 `245785a9b2508575745e134e02425bfe4f62cbabc2e45649e2df382f1549bc50`로 binding된 high-risk approved REQ이다. 현재 CLI는 validation, Discovery confirmation, REQ drafting/rejection만 제공하며 canonical evidence issuance operation은 제공하지 않는다. Root `specbound.yaml`의 `policy.control_plane_adoption.requirements`는 empty이며 유지되어야 한다. Existing validator는 canonical artifact family의 read-side schema/semantic topology를 평가하지만 candidate issuance request의 no-write prevalidation surface는 없다.

## Verification plan

- copied 또는 temporary fixture에서 real CLI를 호출하는 focused tests를 추가한다. 각 `micro-spec`, `iteration-qc`, `delivery-qc` kind에 대해 explicit request parsing·canonical identity derivation·complete candidate input requirement를 확인한다.
- unknown kind, missing/ambiguous/malformed target, absolute/traversal/noncanonical path, invalid candidate content 및 missing/invalid family prerequisite가 structured blocker code/path/detail을 반환하고 requested canonical target이 존재하지 않음을 assert한다.
- success처럼 보이는 bypass가 없도록, full family issuance policy가 아직 implemented되지 않은 kind는 explicit deferred/unsupported structured blocker로 reject됨을 assert한다.
- `.venv/bin/python -m pytest -q`와 `.venv/bin/python -m pytest`를 실행하고, `.venv/bin/python -m specbound.cli preflight`, `.venv/bin/python -m specbound.cli validate`, `git diff --check`를 실행한다.
- production `specbound.yaml` adoption registry가 empty이고 `req-0003-r1` 및 its approval binding SHA-256이 변하지 않았음을 SHA-256 recalculation으로 확인한다.

## QC exit rule

이 slice는 focused copied-fixture tests와 full test suite가 통과하고, root preflight/validate가 valid이며, 모든 selected-AC rejection case가 target absence 및 structured blocker contract를 증명할 때만 `verified` iteration-QC를 요청할 수 있다. 구현이 actual canonical evidence artifact를 publish하거나 AC-003~AC-008을 완료했다고 주장해서는 안 된다. 하나라도 실패하면 failed command와 blocker를 기록하고 `rework` 또는 `blocked`로 유지한다.

## Rollback and containment

이 high-risk slice에서 prevalidation bypass, unsafe path acceptance, requested-target residue 또는 authority leakage가 발견되면 해당 issuance command path를 disabled/reject-only 상태로 되돌리고, affected copied/temporary fixture를 보존하여 재현한다. root adoption registry, approved REQ/approval bytes, existing canonical/manual-bootstrap evidence 및 live Hermes profile은 변경하거나 rollback 대상으로 취급하지 않는다.
