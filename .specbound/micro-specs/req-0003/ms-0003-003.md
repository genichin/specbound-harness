# Micro-SPEC — REQ-0003 slice 003: pre-adoption Micro-SPEC issuance policy

> **Lifecycle boundary:** 이 planning artifact는 exact approved `req-0003-r2`의 AC-003에만 binding된다. 이것과 이후 발급될 review-decision은 approval, adoption, iteration-QC, delivery-QC, merge, delivery 또는 release authority가 아니다. High-risk parent이므로 exact append-only `micro-spec review-decision`의 `approved_for_implementation` verdict가 있어야 이 bounded slice만 구현할 수 있다.

## Objective

AC-001/AC-002의 read-only `issuance-request` 경계 위에, copied fixture에서만 canonical `micro-spec` candidate를 publish하는 pre-adoption policy를 구현한다. publish 전 exact current approved parent REQ의 canonical path, ID, revision, final SHA-256, `approved` status 및 valid approval record binding을 확인한다. 성공은 requested Micro-SPEC planning artifact 하나만 만들고 lifecycle claim 또는 adoption state를 만들지 않는다.

## Scope

- `issuance-request micro-spec`의 explicit publish mode를 추가하되, 기존 default prevalidation-only mode는 변경하지 않는다.
- copied fixture에서 canonical `micro-spec` target 하나에만 complete candidate bytes를 publish한다.
- publish 전 candidate schema/semantic/target binding, exact parent REQ path/ID/revision/digest/status와 canonical approval record의 exact binding을 read-only로 검증한다.
- production `control_plane_adoption.requirements`가 empty인 pre-adoption state를 유지하고, issued Micro-SPEC content/result/help/template이 adoption 또는 lifecycle authority를 주장하지 않게 한다.
- unapproved, missing, malformed, digest-mismatched, superseded, invalid-approval 또는 noncanonical parent를 distinct structured blocker로 reject하고 requested target absence를 보장한다.
- copied fixture positive/negative CLI regression tests에서 target path, exact bytes/digest, parent and approval immutability, adoption-registry immutability 및 non-claiming artifact content를 확인한다.

## Non-goals

- iteration-QC 또는 delivery-QC publication, adopted parent graph resolution(AC-004).
- atomic exclusive competition handling, duplicate policy, fsync, controlled write-failure cleanup 또는 final result digest contract(AC-005~AC-007).
- production fixture 밖의 publish, production adoption registry 변경, approved REQ/approval/review evidence rewrite, live Hermes profile 변경.
- approval, confirmation, adoption, implementation completion, merge, delivery 또는 release authority issuance.

## Baseline

`req-0003-r2`는 high-risk approved REQ이고 final SHA-256은 `e8e3833e7e1b559bd0ed862cfd13b95a7fd2aadce92b89a9aac8df6b135fc354`다. `.specbound/approvals/req-0003-r2.approval.json`은 exact path/ID/revision/risk/digest를 binding한다. 현재 production adoption registry는 empty이며, `ms-0003-002`와 그 review record는 AC-001/AC-002만 binding한다. AC-003은 그것들의 bytes 또는 authority를 확장하지 않는다.

## Verification plan

- copied fixture에서 valid `micro-spec` request를 publish하고 canonical target path와 exact candidate bytes를 assert한다.
- target published 이후 parent REQ, approval record, adoption registry 및 pre-existing evidence의 SHA-256이 unchanged임을 assert한다.
- unapproved, missing, malformed, stale/mismatched, noncanonical, superseded REQ와 malformed/missing/mismatched approval record를 각각 distinct blocker와 target absence로 assert한다.
- default issuance request가 여전히 read-only이고 `micro-spec` publish result/content/help/template이 non-authorizing wording을 유지하는지 assert한다.
- focused tests, `.venv/bin/python -m pytest -q`, `.venv/bin/python -m specbound.cli preflight`, `.venv/bin/python -m specbound.cli validate`, `git diff --check`를 실행한다.

## QC exit rule

AC-003의 copied-fixture positive publish와 every invalid-parent rejection이 pass하고, success가 requested Micro-SPEC target 하나 외의 bytes를 변경하지 않으며, parent/approval/adoption evidence digest가 unchanged이고 full suite·preflight·validate가 pass할 때만 bounded iteration-QC를 요청할 수 있다. 이것은 AC-004~AC-008 또는 authority-bearing lifecycle completion을 주장하지 않는다.

## Rollback and containment

unexpected target mutation, parent/approval/adoption mutation, approval-binding bypass 또는 authority leakage가 보이면 publish mode를 disable/reject-only로 되돌리고 copied fixture evidence와 failed output을 보존한다. containment cleanup은 current copied-fixture invocation이 만든 requested target만 대상으로 하며, production registry, approved REQ/approval, historical review artifacts, existing Micro-SPEC 또는 live Hermes profile은 수정·삭제·rollback하지 않는다.
