# Micro-SPEC — REQ-0003 slice 005: atomic fixture publication

> **Lifecycle boundary:** This planning artifact binds only AC-005 of the exact approved `req-0003-r2` snapshot. Implementation requires a distinct, exact digest-bound `approved_for_implementation` review decision. It grants no approval, adoption, implementation-completion, merge, delivery, or release authority.

## Objective

Replace the fixture-only publication leaf write with a canonical-path-only, same-host/local-filesystem atomic exclusive-create primitive. Exactly one competing publisher may win; every loser or unsafe path fails without changing the winner or escaping the copied fixture.

## Scope

- Derive the target solely from the configured canonical artifact root and validated identity.
- Open publication parent directory without following symlinks; reject symlinked leaf or intermediate components and containment escape before publication.
- Publish a previously absent leaf through atomic exclusive creation; competing writer returns a structured duplicate/conflict blocker and does not mutate existing bytes.
- Limit mutation to the requested leaf in an explicitly marked copied fixture.
- Add isolated regressions for traversal/absolute identity rejection, leaf and intermediate symlink rejection, and deterministic competing publication with one winner and unchanged loser state.

## Non-goals

- Multi-host, network-filesystem, distributed-lock, external-lock, or cross-repository guarantees.
- Flush/fsync/write-failure rollback and final digest result contract (AC-006/AC-007).
- Production adoption mutation, live issuance, lifecycle authority, merge, delivery, or release.

## Baseline

`req-0003-r2` is high-risk and its approval remains valid. `ms-0003-004`/review bind AC-004 only and are not extended. Current fixture-only publication is intentionally non-atomic; AC-005 replaces only that write boundary while preserving prior family prerequisite validation.

## Verification plan

- Focused copied-fixture CLI tests show canonical publication success, duplicate/conflict failure, and byte-for-byte unchanged winner content.
- Test leaf/intermediate symlink and absolute/traversal identity rejection with no external or canonical target mutation.
- Run `.venv/bin/python -m pytest -q tests/test_issuance_request.py`, full pytest, preflight, validate, and `git diff --check`.

## QC exit rule

Success requires a safe canonical leaf created once, with all unsafe/duplicate paths non-mutating.

## Rollback and containment

Any failure is contained to the copied fixture and must leave approved REQ/approval, prior evidence, and production adoption registry unchanged. AC-006 failure-atomicity and AC-007 result-digest behavior remain explicitly deferred.
