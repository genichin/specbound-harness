# Micro-SPEC — REQ-0004 slice 004: fail-closed one-shot Hermes adapter

> **Lifecycle boundary:** 이 planning artifact는 exact approved `req-0004-r1` snapshot의 `CG-3`인 AC-007과 AC-008에만 binding된다. 별도의 exact digest-bound `approved_for_implementation` Micro-SPEC review decision 전에는 구현할 수 없다. 현재 repository는 self-hosting bootstrap/pre-adoption 상태이므로 fake/stub dispatcher evidence와 Bootstrap review/QC를 live Hermes adoption 또는 canonical runtime execution과 구분한다. 이 문서, adapter dispatch/result, Bootstrap advisory 또는 Bootstrap formal QC 평가는 confirmation, approval, canonical Independent Reviewer/IQC publication, Delivery decision, Merge 또는 Release authority가 아니다.

## Objective

Reviewed `ms-0004-001`, `ms-0004-002`, `ms-0004-003`이 확정한 provider-neutral request/result contract, lifecycle/risk/evidence enforcement와 7개 role skill을 변경하지 않고 감싸는 최소 Hermes one-shot adapter를 구현한다. Caller는 exact role request와 reference-result files를 하나의 invocation으로 제출하고, adapter는 core preflight를 먼저 통과한 정확히 한 role만 하나의 adapter-configured model alias와 새 isolated leaf execution/context로 dispatch한다. Adapter는 selected role의 exact skill, repository workdir, allowed tool category/path/mutation boundary만 runtime dispatcher에 노출하고 completion을 공통 `agent-result`로 normalize한 뒤 core validator로 재검증한다. Dispatcher가 isolation·workdir·tool/path 제한을 enforce할 수 없거나 Delivery/Merge/Release/external/production/chain/retry 요청이 있으면 호출 전에 `blocked`, `permitted_next_action: none`, dispatcher call count 0을 반환한다.

## Scope

- `src/specbound/hermes_adapter.py`에 runtime-specific adapter를 캡슐화한다. 이 모듈은 closed adapter config/invocation loader, safe repository-relative path resolver, core preflight 호출, role-to-skill/tool/workdir dispatch-plan builder, injected one-call dispatcher protocol, completion normalization, core result revalidation과 structured blocker를 제공한다. `agent_contract.py`는 provider-neutral finding authority로 유지하며 adapter가 canonical writer, lifecycle transition 또는 live Hermes configuration API를 호출하지 않는다.
- `schemas/hermes-adapter-config.schema.json`과 packaged `src/specbound/schemas/hermes-adapter-config.schema.json`은 version-one closed runtime config를 검증한다. Config는 정확히 하나의 substantive provider-neutral `model_alias`, exact repository workdir `.`, closed provider-neutral-tool-category→Hermes runtime tool-name mapping과 required dispatcher capability set만 표현한다. Role별 model/provider/profile override, secret/credential, network endpoint, session reuse, authority identity/action 또는 lifecycle transition field는 허용하지 않는다.
- `schemas/hermes-invocation.schema.json`과 packaged copy는 exactly-one invocation envelope을 검증한다. Envelope은 `schema_version`, one safe repository-relative core `request_file`, unique ordered `reference_result_files`, adapter config path와 optional noncanonical result destination만 포함한다. `roles`, `next_role`, `chain`, `retry`, `scheduler`, `concurrency`, provider/model/profile override, tool/workdir override, Delivery/Merge/Release, external/production mutation 또는 authority action field는 additional-property failure로 거부한다.
- Runtime config의 tool mapping은 machine policy의 `repository-read`, `candidate-write`, `test-execute`, `filesystem-metadata` 네 category만 exact key로 가진다. Adapter는 selected role policy의 category set을 runtime tool-name allowlist로 변환하고 policy의 exact `skill_path`, `allowed_path_patterns`, `mutation_classes`, `output_kinds`, planned execution/context IDs와 target reference를 immutable dispatch plan에 포함한다. Config에 unknown/missing category, duplicate tool, wildcard tool, shell/network/secret/authority helper 또는 category가 허용하지 않은 tool이 있으면 dispatch 전에 거부한다.
- Injected dispatcher는 capability descriptor와 exactly-one `dispatch(spec)` seam을 제공한다. Required capability는 `fresh_leaf_context`, `single_model_alias`, `exact_workdir`, `exact_skill_binding`, `tool_allowlist`, `path_boundary`, `no_context_reuse`, `structured_completion`이다. `exact_skill_binding`은 dispatcher가 dispatch spec의 exact repository-relative `skill_path`와 SHA-256에 binding된 skill bytes만 selected leaf context에 적용하고 다른·stale·추가 skill을 대체 또는 병합하지 않는 enforceable contract다. 하나라도 false/missing/unprovable이면 adapter는 `dispatched: false`, call count 0, `permitted_next_action: none`을 반환하고 dispatcher를 호출하지 않는다. Fake/stub dispatcher는 이 seam을 deterministic하게 구현하지만 live Hermes profile/tool configuration을 만들거나 변경하지 않는다.
- Dispatch spec은 role 하나, `leaf` execution, repository root workdir, configured model alias, exact role skill path 및 SHA-256, selected core request/target/reference digests, planned execution/context IDs, allowed tools/path/mutation/output와 forbidden action/claim을 포함한다. Dispatcher는 call-time에 적용한 skill path/SHA binding을 structured completion metadata로 반환하고 adapter는 planned binding과 exact equality를 재검증한다. Wrong/stale/ignored/substituted/additional skill binding은 result normalization 전에 `blocked`로 종료하며 다음 dispatch나 retry를 수행하지 않는다. Dispatcher API에 role list, next-role, retry/loop, authority transition, external target 또는 automatic lifecycle transition을 전달할 수 없다.
- Adapter는 core `validate_configured_role_request`를 dispatcher 호출 전에 실행하고 exact target/current state/risk/reference/eligibility/capability blocker를 그대로 fail-closed 전파한다. Core preflight가 invalid이면 `dispatched: false`, call count 0, `permitted_next_action: none`이며 result destination이나 canonical path를 만들지 않는다.
- Dispatcher completion은 exact planned/actual execution/context IDs, structured role output와 completion metadata를 가진 closed runtime envelope이어야 한다. Adapter는 request/config에서 role, task, model alias, exact target, references와 clean context provenance를 결합하고 runtime-only envelope field를 제거해 provider-neutral `agent-result` candidate를 만든다. Prose/fence, malformed/extra field, runtime/provider/session leakage, wrong role/target/model alias, execution/context reuse/mismatch, unauthorized changed path/tool/action/claim, non-substantive evidence 또는 invalid verdict/action은 core result validation으로 거부한다.
- Result normalization과 validation은 temporary external/copy-fixture bytes에서 먼저 수행한다. Validated result만 caller가 명시한 safe noncanonical candidate destination에 no-overwrite atomic write할 수 있다. Destination 생략 시 validated mapping만 반환하고 repository를 쓰지 않는다. Failure/cancellation/timeout/malformed completion은 partial result, canonical evidence, authority record 또는 target mutation을 남기지 않는다.
- `tests/test_hermes_adapter.py`와 `fixtures/hermes-adapter/`에 actual 7-role policy/skills를 사용하는 config/invocation/fake-dispatcher matrix를 추가한다. Existing `tests/test_agent_contract.py`에는 core policy/request/result schema가 `delegate_task`, Hermes tool/workdir/session/provider fields를 계속 거부하는 explicit leakage regression만 최소 추가한다. Adapter tests는 live Hermes, credential, provider API 또는 network에 의존하지 않는다.
- Source checkout과 non-editable installed wheel은 같은 external copied fixture에서 config/invocation preflight, seven-role mapping, zero-call refusal 및 completion normalization verdict/blocker를 동일하게 반환해야 한다. Hermes package를 SpecBound runtime dependency에 추가하지 않고 `pyproject.toml`의 provider-neutral dependency boundary를 유지한다.
- 현재 exposed Hermes `delegate_task` schema가 per-call model/tool/workdir/skill enforcement 또는 synchronous structured completion contract를 제공하지 않는 경우 이를 live success로 우회하지 않는다. Capability descriptor를 충족하는 injected dispatcher만 실행 가능하며, 현재 runtime integration이 부족하면 deterministic `blocked`/zero-call evidence로 남긴다. Fake/stub success는 adapter contract evidence이지 live Hermes deployment claim이 아니다.

### One-shot state machine

1. `load`: adapter config와 invocation을 closed schema로 읽고 safe path·physical identity·no-overwrite destination을 검증한다.
2. `core-preflight`: exact request/reference bytes를 provider-neutral core validator로 재검증한다.
3. `capability-check`: dispatcher enforcement capabilities와 single configured model alias, exact skill path/SHA binding, workdir/tool/path mapping을 검증한다.
4. `dispatch-once`: selected role 하나의 immutable spec으로 dispatcher를 정확히 한 번 호출한다.
5. `normalize`: untrusted completion을 provider-neutral result candidate로 변환하고 runtime field를 제거한다.
6. `core-result-check`: exact target/reference bytes를 다시 읽어 result를 core validator로 검증한다.
7. `return-or-publish-candidate`: valid mapping을 반환하거나 safe noncanonical destination에 atomic no-overwrite write한다. 어떤 단계의 failure도 다음 단계/역할을 선택하거나 retry하지 않는다.

## QC exit rule

이 slice는 exact approved parent와 reviewed `ms-0004-004` binding, reviewed predecessor three-slice digests, exactly-one role invocation, one configured model alias, fresh leaf execution/context, exact role skill path/SHA binding과 tool/workdir/path/mutation mapping, `exact_skill_binding` 포함 capability-enforcing dispatcher preflight, false/missing/unprovable capability zero-call, wrong/stale/ignored/substituted/additional skill binding blocked/no-retry, core request zero-call refusal, call count 1 success/no retry, provider-neutral completion normalization과 core result revalidation, seven-role positive mapping, missing/ineligible/forbidden/multi-role/chain/retry/authority/Delivery/Merge/Release/external/production negative matrix, malformed/failed completion no-partial-result, result destination atomic no-overwrite, core runtime-field leakage rejection, source/non-editable-wheel parity 및 exact-head Ubuntu Python 3.11/3.12 전체 CI가 모두 통과할 때만 단일 Bootstrap formal Iteration-QC 평가 후보를 요청한다.

Bootstrap formal QC가 통과해도 canonical IQC record, live profile rollout, Delivery decision, Merge 또는 Release를 주장하지 않으며 `ms-0004-005` 진행은 accountable user의 별도 explicit bootstrap decision과 별도 reviewed Micro-SPEC에 한정한다.
