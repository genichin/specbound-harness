# Micro-SPEC — REQ-0004 slice 005: integration evidence, compatibility, and opt-in guidance

> **Lifecycle boundary:** 이 planning artifact는 exact approved `req-0004-r1` snapshot의 마지막 completion group `CG-4`인 AC-009와 AC-010에만 binding된다. 별도의 exact digest-bound `approved_for_implementation` Micro-SPEC review decision 전에는 구현할 수 없다. 현재 repository는 self-hosting bootstrap/pre-adoption 상태이고 `req-0004-r1`은 `policy.control_plane_adoption.requirements`에 등록되지 않았다. 따라서 source/wheel/CI evidence와 fresh-context Bootstrap review/QC는 canonical Independent Reviewer 실행, canonical IQC/DQC publication, live Hermes adoption, Delivery decision, Merge 또는 Release authority가 아니다.

## Objective

Reviewed `ms-0004-001`부터 `ms-0004-004`까지 구현된 provider-neutral 7-role policy/result contract, independence/risk/evidence/lifecycle validation, repository-backed role skills와 fail-closed one-shot Hermes adapter를 변경 없이 하나의 repository integration evidence contract로 묶는다. 실제 repository와 copied fixtures, public CLI help, source checkout, disposable non-editable installed wheel 및 Ubuntu Python 3.11/3.12 CI에서 positive/negative/no-mutation matrix를 결정적으로 검증한다. 동시에 README, governance, adopter guidance와 template opt-in 설명을 실행 가능한 contract와 같은 용어로 정렬하되 기존 manual lifecycle workflow와 agent-contract-disabled adopter를 계속 지원한다.

이 slice의 사용자 관찰 가능 결과는 다음과 같다.

1. Maintainer는 하나의 documented verification sequence로 role policy, 7 skills, request/result validation, risk/independence/lifecycle blockers와 Hermes adapter fixture evidence를 재현할 수 있다.
2. Installed wheel은 source checkout과 동일한 7-role 및 adapter positive/negative verdict를 반환하며 checkout source를 우연히 import하지 않는다.
3. Agent contract를 opt in하지 않은 adopter는 기존 manual lifecycle validation을 계속 통과하고, opt in한 adopter만 repository-owned policy와 skill inventory를 제공해야 한다.
4. 문서와 CLI help는 provider-neutral contract, repository-local role skills, one configured model alias, isolated one-shot context와 capability-enforcing injected adapter를 정확히 구분하고 fake/stub evidence를 live Hermes deployment로 표현하지 않는다.

Reference-result file set은 role policy의 required/optional/forbidden edge를 정확히 따른다.
- Cross-slice regression row는 Effective Task Risk ordering, producer/reviewer/QC planned/actual execution-context separation, safe direct-reference resolution, required evidence applicability, current canonical lifecycle eligibility와 advisory no-authority behavior의 대표 positive 및 reason-specific negative assertions을 실행한다. 이 row는 기존 `tests/test_agent_contract.py`의 complete matrix를 대체하지 않으며 affected regression gate로 유지한다.
- Hermes adapter row는 actual 7-role policy와 skill bytes를 사용해 동일 configured model alias, fresh leaf execution/context, exact root workdir, skill path/SHA, closed category-to-runtime-tool mapping과 one-call success를 7개 역할 모두에서 검증한다. Unsupported/missing capability, forbidden shell/network/secret/authority/wildcard/unknown/misclassified tool, multi-role/chain/retry, authority/Delivery/Merge/Release, external/production mutation 및 malformed completion은 call count 0 또는 최대 1의 정확한 단계에서 `blocked`, `result: null`, `permitted_next_action: none`, no retry로 종료되어야 한다.
- Immutable input row는 core preflight 전후 request/direct-reference replacement, dispatch 중 reference replacement와 core result validation 중 reference replacement를 각각 검사한다. - Test helper가 negative fixture를 mutate할 때 bytes가 실제로 달라졌음을 먼저 assert하고, expected blocker code를 확인한다. Generic non-zero 또는 unrelated schema failure만으로 intended fail-closed behavior를 통과시킬 수 없다.

Integration test/fixture, CI, CLI help 또는 guidance 변경이 predecessor behavior를 깨뜨리거나 source/wheel drift, false live-adoption claim, manual adopter regression 또는 unrelated formatting churn을 만들면 이 slice가 추가·변경한 test/fixture/CI/help/guidance bytes만 exact planning baseline으로 되돌린다. 그 뒤 predecessor focused suites, root preflight/validate/docs, source/wheel parity와 exact protected artifact digests를 재검증한다.

Failure injection과 mutation tests는 isolated copied repository 또는 OS temporary directory에서만 실행한다. 각 실패 전후에 target, destination, canonical lifecycle/evidence/authority roots, `specbound.yaml` 및 live repository status를 비교한다. Test cleanup은 operation-owned disposable path만 제거하며 competing/existing target을 삭제하지 않는다. CI wheel/build metadata는 별도 disposable archive/venv에만 생성한다.

Approved `req-0004-r1`, approval/confirmation/review/rejection/reconsideration records, predecessor Micro-SPEC/review/QC evidence, `.specbound/policies/agent-roles.yaml`, seven role `SKILL.md`, `specbound.yaml` authority allowlists와 `policy.control_plane_adoption`, live Hermes profile/config/user memory/auth/credential은 rollback 대상이 아니며 변경하지 않는다. Historical canonical prose를 terminology 정렬 목적으로 수정하지 않는다.

Integration RED가 `agent_contract.py`, `hermes_adapter.py`, role policy/schema, role skill metadata/body, lifecycle validator/writer 또는 authority config의 production semantic 변경 없이는 닫히지 않는 accepted-invalid predecessor gap을 발견하면 implementation을 멈춘다. Reproduction, affected AC와 exact file/line을 기록하고 `ms-0004-005` rework 또는 predecessor-specific follow-up governance를 결정한다. External/network/secret/production write, canonical evidence/authority record write, live profile mutation, retry/fan-out 또는 partial target이 관찰되면 즉시 `blocked`로 처리하고 해당 implementation attempt를 폐기한다.
