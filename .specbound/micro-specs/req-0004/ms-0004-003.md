# Micro-SPEC — REQ-0004 slice 003: repository-backed role skills and policy alignment

> **Lifecycle boundary:** 이 planning artifact는 exact approved `req-0004-r1` snapshot의 AC-002에만 binding된다. 별도의 exact digest-bound `approved_for_implementation` Micro-SPEC review decision 전에는 구현할 수 없다. 현재 repository는 self-hosting bootstrap/pre-adoption 상태이므로 review와 Iteration-QC 실행 evidence를 canonical live-adoption claim과 구분한다. 이 문서, role skill, Bootstrap advisory 또는 Bootstrap formal QC 평가는 confirmation, approval, canonical Independent Reviewer/IQC publication, Delivery decision, Merge 또는 Release authority가 아니다.

## Objective

Reviewed `ms-0004-001`과 completed Bootstrap implementation slice `ms-0004-002`가 확정한 provider-neutral 7-role machine policy를 사람이 실행 가능한 repository-backed 절차와 1:1로 정렬한다. 정확히 7개의 stable role ID 각각은 `skills/{role-id}/SKILL.md` 하나에 binding되고, 각 skill의 machine-readable frontmatter와 필수 body boundary는 policy의 required input, output, path/tool/mutation, lifecycle eligibility, result reference, permitted next action 및 forbidden action/claim보다 넓은 권한을 표현할 수 없다. Root validation과 read-only CLI는 missing/orphan/duplicate/misaligned/unsafe skill을 fail-closed하게 거부하고 어떤 검증도 lifecycle state나 authority record를 변경하지 않는다.

## Scope

- `.specbound/policies/agent-roles.yaml`의 각 role entry에 exact safe POSIX-relative `skill_path: skills/{role-id}/SKILL.md`를 추가한다. `schemas/agent-roles.schema.json`, packaged `src/specbound/schemas/agent-roles.schema.json`, repository/fixture policy copies와 `_EXPECTED_ROLE_CONTRACTS`는 이 closed field에 정렬한다. 역할 수, role ID, 기존 permission/risk/evidence/reference/lifecycle contract는 변경하지 않는다.
- 다음 정확한 repository-backed skill 7개를 추가한다: `skills/discovery-author/SKILL.md`, `skills/requirement-author/SKILL.md`, `skills/micro-spec-author/SKILL.md`, `skills/independent-reviewer/SKILL.md`, `skills/implementation/SKILL.md`, `skills/iteration-qc/SKILL.md`, `skills/delivery-qc/SKILL.md`. 기존 `skills/specbound-harness`, `skills/confirm-discovery`, `skills/draft-req`, `skills/review-req`는 변경하거나 대체하지 않는다.
- 각 skill은 byte 0의 YAML frontmatter와 non-empty Markdown body를 사용한다. Frontmatter는 `name == role_id`, substantive `description`, version/author/license, `metadata.hermes`, closed `metadata.specbound` mapping을 포함한다. `metadata.specbound`는 schema version, role ID, exact policy/skill path, required inputs, allowed path patterns/tool categories/mutation classes/output kinds, lifecycle eligibility, result-reference cardinality, permitted next actions, forbidden actions/claims, `authority_type: none`, `self_review: false`, `self_approval: false`를 표현하며 corresponding policy entry와 exact set/list semantics로 일치해야 한다.
- Body는 `Overview`, `When to Use`, `Required Inputs`, `Allowed Operations`, `Forbidden Actions and Claims`, `Procedure`, `Verification`, `Rework and Blocked`, `Completion Checklist` headings를 모두 가진다. 모든 role skill은 machine policy가 authority이고 skill은 procedural guidance뿐이라는 boundary, self-review/self-approval 금지, confirmation/approval/review-decision/verified/delivery/canonical publication/Merge/Release/external mutation claim 금지를 동일한 normative 문장으로 명시한다. Validator는 필수 boundary 누락과 closed over-authorizing phrase fixture를 거부하되 forbidden behavior를 설명하는 `must not`/`never` 문구는 오탐으로 거부하지 않는다.
- 역할별 절차는 policy의 exact input, allowed mutation과 evidence slot을 사람이 실행 가능한 순서로 설명한다. Author 3개는 자신의 candidate family만 작성하고 review를 요청한다. Independent Reviewer는 read-only/`changed_paths: []`를 유지한다. Implementation은 reviewed Micro-SPEC scope만 변경하고 Iteration-QC를 요청한다. IQC/DQC는 자신의 candidate evidence family만 작성하며 DQC는 Delivery decision을 내리지 않는다. 모든 output은 provider-neutral non-authorizing `agent-result`이고 allowed `permitted_next_action`만 사용한다.
- `src/specbound/agent_contract.py`에 read-only `validate_agent_role_skills(root, policy_path)`를 추가한다. 기존 safe repository path/canonical spelling/symlink containment을 재사용해 skill path가 exact regular file인지 확인하고, frontmatter parse/closed shape, role/name/path uniqueness, policy field alignment, required headings/boundary, no-overauthority phrase, orphan role-skill inventory를 검증한다. 검증 결과는 checked skill 수와 distinct blocker를 제공하며 repository bytes를 변경하지 않는다.
- `src/specbound/validation.py`는 `policy.agent_contract.enabled: true`일 때 policy validation 후 skill alignment validation도 실행하고 payload에 `checked_agent_skills`를 노출한다. `src/specbound/cli.py`는 read-only `specbound agent validate-skills`를 추가해 동일 validator 결과를 출력한다. 기존 request/result validator, authority writer, selector, lifecycle transition 및 agent result semantics는 변경하지 않는다.
- `tests/test_agent_contract.py`에 actual 7-role positive inventory와 missing/orphan/duplicate role mapping, wrong role/name/path, unsafe absolute/traversal/backslash/case-variant/symlink path, malformed/extra frontmatter, widened path/tool/mutation/output/lifecycle/next action, removed forbidden action/claim, `authority_type` 변경, self-review/self-approval, missing body heading/boundary 및 over-authorizing phrase negative fixture를 추가한다. 각 blocker 전후 repository snapshot을 비교해 zero mutation을 확인한다.
- `fixtures/valid-minimal`은 active agent contract의 positive root-validation fixture이므로 동일한 7-role skill inventory를 포함한다. Test-only copied roots는 actual skills를 copy하여 독립 mutation fixture를 만든다. `fixtures/agent-contract` 및 policy copies는 새 required `skill_path` field와 schema에 정렬하되 unrelated unsafe-path fixture의 기존 blocker 의미를 변경하지 않는다.
- Source checkout과 non-editable installed wheel의 `agent validate-skills`는 동일 repository root에서 같은 role/skill count와 verdict를 반환해야 한다. Wheel은 adopter repository의 skill bytes를 읽고 검증하며 Hermes profile 또는 user-local skill tree를 설치·수정·탐색하지 않는다.

## Rollback and containment
