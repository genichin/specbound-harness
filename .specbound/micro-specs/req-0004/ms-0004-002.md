# Micro-SPEC — REQ-0004 slice 002: independence, task risk, evidence, and lifecycle eligibility

> **Lifecycle boundary:** 이 planning artifact는 exact approved `req-0004-r1` snapshot의 `CG-2`인 AC-004, AC-005, AC-006에만 binding된다. 별도의 exact digest-bound `approved_for_implementation` Micro-SPEC review decision 전에는 구현할 수 없다. 현재 repository는 self-hosting bootstrap/pre-adoption 상태이므로 review와 Iteration-QC 실행 evidence를 canonical live-adoption claim과 구분한다. 이 문서, agent result, Bootstrap advisory 또는 Bootstrap formal QC 평가는 confirmation, approval, canonical IQC publication, Delivery decision, Merge 또는 Release authority가 아니다.

## Objective

Reviewed `ms-0004-001`의 provider-neutral 7-role request/result contract 위에 cross-result 독립성 및 exact provenance, `Effective Task Risk = max(target artifact risk, task-kind floor)`, mutation별 evidence applicability, current canonical state 기반 lifecycle eligibility를 fail-closed하게 구현한다. 같은 provider-neutral model alias는 허용하되 Producer↔Independent Reviewer, Implementation↔Iteration-QC, Delivery-QC↔Delivery authority의 execution/context와 authority action을 분리한다. Effective Task Risk는 실행 통제와 evidence 깊이만 선택하고, authority-bearing transition의 allowlist는 기존과 같이 target artifact의 canonical risk만 사용한다. 어떤 advisory `pass`도 canonical state나 authority record를 만들거나 바꾸지 않는다.

## Scope

- `.specbound/policies/agent-roles.yaml`과 `schemas/agent-roles.schema.json` 및 packaged schema에 version-one risk/evidence contract를 추가한다. Risk 순서는 정확히 `low < medium < high`이고 task floor는 Discovery/REQ/Micro-SPEC author `low`, Independent Reviewer/Implementation/Iteration-QC/Delivery-QC `medium`이다. Confirmation/approval/Delivery decision/Merge/Release와 `authority_transition`/`external_mutation`은 7개 agent role이 실행할 수 없는 `high` 경계로 표현한다.
- Risk contract는 role 수를 바꾸지 않고 각 role/task의 floor, 허용 mutation class, required/conditional evidence slot 및 substantive `not_applicable` 규칙을 closed shape로 정의한다. Unknown risk, task kind, mutation class, evidence slot 또는 risk 하향은 distinct blocker다. Security/authentication/authorization, destructive/irreversible, lifecycle authority, production/release 및 external mutation은 agent contract에서 강제 `high` 또는 unsupported로 fail-closed한다.
- `src/specbound/agent_contract.py`에 stage-sensitive artifact-family canonical risk resolver와 ordered maximum helper를 추가한다. Discovery `draft|in_review`는 exact current snapshot의 proposed `risk_class`, confirmed downstream은 exact confirmation-bound snapshot/risk를 사용한다. REQ `draft|in_review|rejected`는 exact current snapshot의 `risk`와 confirmed parent risk monotonicity를 검증하고, approved downstream은 exact approval-bound snapshot/risk를 사용한다. Micro-SPEC은 exact approved REQ, iteration-QC는 exact reviewed Micro-SPEC→approved REQ, delivery-QC는 exact approved REQ와 verified IQC ancestry에서 risk를 상속한다. 각 stage에서 missing/stale/digest·identity mismatch, conflicting parent/record와 chain risk downgrade는 risk를 추정하지 않고 distinct blocker로 거부한다. `validate_role_request`는 caller가 risk를 선택하게 하지 않고 이 resolver 결과와 selected role floor에서 `target_risk`/`effective_task_risk`를 도출해 결과에 노출하며 external/production/authority-transition capability를 delegation 전에 거부한다. `validate_agent_result`는 payload risk 두 필드가 resolver 및 ordered maximum과 정확히 일치하는지 검사한다. 낮춘 risk, unknown/unsupported mutation, task-risk를 authority selector 또는 authority claim으로 사용하는 결과는 거부하며 `critical` 같은 version-one 외 risk는 schema와 semantic validator 모두에서 거부한다.
- Existing closed result reference envelope `{result_id, role_id, execution_id, context_id, sha256}`는 변경하지 않는다. Agent request에는 caller가 미리 선택한 provider-neutral `planned_execution_id`와 `planned_context_id`를 closed required field로 추가하고 result-time actual IDs와 동일하게 pre-execution 독립성을 검사한다. `validate_role_request`/`validate_agent_result`와 기존 read-only agent CLI에는 repeatable explicit `--reference-result-file FILE` input을 추가하고 caller가 전달한 noncanonical result bytes만 `result_id`로 unique-index한다.
- Policy는 consumer별 reference edge를 machine-readable하게 고정한다. Independent Reviewer의 producer는 target family와 같은 Discovery/REQ/Micro-SPEC author result, Implementation의 reviewer는 exact target Micro-SPEC의 Independent Reviewer result, Iteration-QC의 producer/reviewer는 exact target Micro-SPEC의 Implementation/Independent Reviewer result여야 한다. Delivery-QC는 단일 result reference로 verified IQC set을 왜곡하지 않도록 `producer_result_ref: null`과 `reviewer_run_ref: null`을 요구하고 exact approved REQ를 target으로 삼으며, `verified-iteration-qc-set` input 및 provenance의 모든 canonical IQC를 complete/unique하게 해석해 각 IQC→reviewed Micro-SPEC→approved REQ ancestry와 full AC coverage를 검증한다. DQC↔Delivery authority 분리는 `authority_type: none`, null action, empty claims 및 no-writer/no-mutation으로 집행한다. Optional reference가 존재할 때도 해당 consumer의 closed edge를 적용한다. Referenced verdict는 해당 handoff를 허용하는 `pass`여야 하며 wrong role/target/stage/verdict, self-reference, planned/actual execution 또는 context overlap과 producer↔reviewer overlap은 각각 distinct blocker다. 같은 `model_alias`는 fresh execution/context와 exact forwarded inputs가 충족되면 허용한다.
- `--reference-result-file`은 repository root 안의 normalized safe POSIX-relative regular file만 허용한다. Absolute/traversal/backslash, symlink component/target, out-of-root, duplicate physical file/alias spelling, duplicate result ID, conflicting digest, undeclared 또는 extra file은 fail-closed한다. Provenance에서 reference result는 exact `{path: normalized repository-relative path, id: result_id, revision: null, sha256: file bytes digest}`로 표현한다. Resolver는 referenced bytes의 closed schema와 intrinsic result/role/execution/context/target identity를 재검증하고 Result validation에서 exact provenance declaration을 요구한다. 새 canonical agent-result root나 retrospective result record는 만들지 않는다.
- Independent Reviewer는 `mutation_class: none`, `changed_paths: []`, no-write evidence를 유지한다. Iteration-QC/Delivery-QC의 `evidence_write`는 자신의 candidate evidence family에만 제한하고 implementation source `changed_paths`는 허용하지 않는다. 한 결과가 verdict와 authority action/claim을 동시에 표현하거나 DQC `pass`를 Delivery decision으로 승격하면 차단한다.
- Evidence applicability는 Discovery §9c의 여섯 mutation class `none`, `candidate_write`, `repository_mutation`, `evidence_write`, `authority_transition`, `external_mutation`을 machine-readable하게 표현한다. 7개 agent role은 앞의 네 종류만 role별 최소 권한으로 사용할 수 있다. Required evidence는 `provided`여야 하며, conditional slot의 `not_applicable`은 해당 task/mutation/risk에서 policy가 허용하고 reason이 substantive할 때만 통과한다. High-risk repository mutation에는 focused test, negative test, affected regression, rollback/no-partial-mutation 및 전체 지원 CI evidence가 모두 필요하다.
- Lifecycle eligibility는 repository에서 exact target과 family-specific parent/confirmation/review-submission/review-decision/rejection/reconsideration/approval/Micro-SPEC review/IQC evidence를 다시 읽고 validated reference edge를 결합해 계산한다. Transition crosswalk는 Discovery confirmation→`discovery_confirmation_authorities_by_risk`, REQ review decision→`requirement_review_decision_authorities_by_risk`, rejection→`requirement_review_authorities_by_risk`, reconsideration→`requirement_reconsideration_authorities_by_risk`, approval→`requirement_approval_authorities_by_risk`, Micro-SPEC review→`micro_spec_review_authorities_by_risk`, DQC verification→`delivery_qc_authorities_by_risk` 및 각각의 existing canonical writer로 닫는다. Missing/stale/digest·identity mismatch/unauthorized record마다 distinct blocker와 `permitted_next_action: none`을 반환한다. Existing selector/writer와 `specbound.yaml` bytes는 변경하지 않고 selector input은 Effective Task Risk가 아니라 canonical Artifact Risk임을 table-driven assertion으로 고정한다. `req to-in-review`는 selector/authority 인수 없는 non-authorizing submission으로 유지한다.
- `src/specbound/cli.py`는 기존 read-only `agent check-role-request`와 `agent validate-result`에 repeatable `--reference-result-file FILE`만 추가한다. Core resolver의 derived state/risk/advisory/blocker를 serialize하되 writer를 호출하지 않는다. `tests/test_agent_contract.py`와 `fixtures/agent-contract/`에 low/medium/high × 7 task floor matrix, mutation/evidence applicability positive/negative matrix, same-model fresh-context success, producer/reviewer/QC execution/context overlap, missing/ambiguous/extra/stale referenced result, high-risk missing evidence, external/authority mutation, advisory pass no-escalation 및 exact canonical snapshot no-mutation cases를 추가한다.
- `schemas/agent-result.schema.json`, packaged schema, three repository policy copies, fixture payload와 CLI result serialization을 risk/reference contract와 정렬한다. Source checkout과 installed wheel은 동일 provider-neutral contract를 검증해야 한다. `src/specbound/validation.py`, `src/specbound/requirement_lifecycle.py`, `src/specbound/micro_spec_lifecycle.py`, `src/specbound/issuance_request.py`와 `specbound.yaml`은 regression 검증 대상이지만 production 변경 대상이 아니다.

## QC exit rule

이 slice는 exact approved parent와 reviewed `ms-0004-002` binding 유지, pre-authority부터 downstream까지 stage-sensitive canonical-risk inheritance와 missing/stale/mismatched edge matrix, exact cross-result resolution 및 repository-safe reference path matrix, consumer별 role/target/stage/verdict edge, DQC의 exact approved-REQ target과 complete unique verified-IQC-set/null result-reference contract, planned/actual pairwise independence와 same-model/fresh-context 허용, 전체 risk-floor 계산 matrix, task/mutation evidence applicability positive/negative matrix, high-risk evidence completeness, external/authority mutation 차단, transition별 resolver/selector/writer crosswalk 및 unauthorized/missing/stale record failure matrix, advisory pass zero-mutation, provider-neutral Hermes-free source/installed-wheel parity 및 지원 Ubuntu Python 3.11/3.12 전체 CI가 모두 통과할 때만 Bootstrap formal Iteration-QC 평가 후보를 요청한다.

하나라도 실패하면 verdict는 `rework` 또는 `blocked`다. Bootstrap 평가가 통과해도 canonical IQC record, live adoption, Delivery decision, Merge 또는 Release를 주장하지 않으며 다음 slice 진행은 accountable user의 explicit bootstrap decision과 별도 reviewed Micro-SPEC에 한정한다.

## Rollback and containment

구현 전 changed-path inventory와 기존 bytes/digest를 기록한다. 이 high-risk slice가 risk 하향, provenance/reference bypass, selector drift, evidence over-permission, partial write 또는 packaging regression을 만들면 `.specbound/policies/agent-roles.yaml`, agent schema/package copies, `src/specbound/agent_contract.py`, related fixture/tests/CLI serialization 중 이 slice 변경만 exact baseline으로 되돌린다. 그 뒤 focused/full tests, root validation, existing lifecycle transition tests, source/installed-wheel parity와 canonical artifact digest 불변을 재검증한다.

Approved REQ, approval/confirmation/review/rejection/reconsideration records, existing canonical evidence, transition authority allowlists, `policy.control_plane_adoption` 및 live profile/config는 rollback 대상이 아니며 변경하지 않는다. 외부·production·secret/network write, authority record write, implementation source를 변경하는 reviewer/QC, canonical target partial file 또는 unexpected lifecycle transition이 관찰되면 즉시 `blocked`로 처리하고 해당 실행을 폐기한다.
