# Micro-SPEC — REQ-0005 slice 002: independent live Iteration-QC authority and writer

> **Lifecycle boundary:** 이 planning artifact는 exact approved `req-0005-r1` snapshot의 AC-003에만 binding된다. Candidate authoring과 advisory review는 authority가 아니다. High-risk parent의 canonical `micro-spec review-decision`이 이 exact Micro-SPEC SHA-256에 `approved_for_implementation`을 기록하기 전에는 구현을 시작할 수 없다. 그 결정도 copied/isolated repository에서 writer capability를 구현·검증하는 것만 허용하며 live adoption, live IQC publication, canary, activation, DQC, Delivery, Merge, Release 또는 rollout을 허용하지 않는다.

## Objective

기존 iteration-QC artifact family를 exact adopted REQ, reviewed Micro-SPEC, implementation result, independent evaluator result와 별도 accountable authority action에 bind하고, implementation self-QC와 evaluator/authority 결합을 fail closed하게 거부하는 distinct `specbound iteration-qc decide` writer를 구현한다. Writer는 supported POSIX repository의 allowlisted canonical target 하나만 failure-atomic하게 exclusive-create하며, agent/evaluator verdict나 green tests 자체를 canonical authority로 승격하지 않는다.

## Scope

### 1. Independent IQC authority policy

- `specbound.yaml`, `templates/specbound.yaml` 및 정상 copied fixtures에 `policy.iteration_qc_authorities_by_risk`를 exact closed mapping으로 추가한다.
  - `low: [repository-maintainer]`
  - `medium: [repository-maintainer]`
  - `high: [independent-advanced-llm-reviewer]`
- Validator는 세 risk key의 exact ordered membership을 요구한다. 누락·추가 risk, 빈/중복 identity, 순서 변경, generic fallback, alias, runtime override 또는 high-risk의 `repository-maintainer` 추가는 `malformed_config`로 거부한다.
- IQC writer는 bound approved REQ의 current risk로 selector를 해석한다. `low|medium`에서 authority identity가 implementation actor와 같으면 allowlisted identity여도 self-QC로 거부하고, `high`에서는 exact `independent-advanced-llm-reviewer`만 허용한다.
- 구현 actor, evaluator, canonical authority는 각각 non-placeholder identity/action/context를 가져야 한다. Implementation 및 evaluation result의 `action_id`와 canonical authority의 `authority_action_id`, 그리고 세 `context_id`는 각각 pairwise distinct여야 한다. Identity가 같더라도 action/context overlap은 허용하지 않지만 evaluator와 authority identity 자체의 동일성은 별도 action/context라면 허용한다. Implementation actor와 canonical authority identity가 같으면 모든 risk에서 self-QC로 거부한다.

### 2. Authority-bound iteration-QC record profile

- `schemas/iteration-qc.schema.json`과 packaged exact-byte mirror `src/specbound/schemas/iteration-qc.schema.json`, `templates/iteration-qc.json`을 AC-003 live-writer profile로 정렬한다. Read-only candidate inputs에는 closed `schemas/iteration-qc-implementation-result.schema.json`, `schemas/iteration-qc-evaluation-result.schema.json`과 두 packaged mirrors를 사용한다. Canonical JSON은 UTF-8 without BOM, LF, sorted object keys, two-space indentation, `ensure_ascii: false`, exactly one trailing LF다.
- Live writer가 발행하는 schema-version 1 record는 additional properties를 금지하고 다음 closed fields를 요구한다.
  - `schema_version: 1`
  - exact approved `requirement: {path, id, revision, sha256}`
  - exact effective IQC adoption `adoption: {path, sha256, transition: iteration_qc}`
  - exact reviewed `micro_spec: {path, id, sha256}`와 `micro_spec_review: {path, sha256}`
  - Micro-SPEC과 같은 ordered `selected_acceptance_criteria`
  - exact input bytes를 보존하는 `implementation_result: {result_id, sha256, source_commit, actor, action_id, context_id}`
  - exact input bytes와 implementation edge를 보존하는 `evaluation_result: {result_id, sha256, implementation_result_id, implementation_result_sha256, evaluator, action_id, context_id}`
  - `authority: {identity, authority_action_id, context_id}`
  - current policy binding `policy: {path: specbound.yaml, sha256, selector: iteration_qc_authorities_by_risk}`
  - non-empty `verification` entries `{command, result: passed, exit_code: 0}`
  - exact `verdict: verified`
  - exact parent AC set minus selected ACs인 ordered `remaining_acceptance_criteria`
  - writer-generated UTC RFC3339 `decided_at`
- Lowercase SHA-256, full lowercase SHA-1 Git object ID, safe canonical paths, Unicode NFC, non-placeholder identity/action/context/command를 요구한다. Requirement, adoption, Micro-SPEC, review, policy digest와 path/ID/revision/slice coupling은 record와 repository bytes에서 모두 재계산한다.
- 기존 unscoped fixture/history의 six-field iteration-QC v1 record는 ordinary repository validation에서 compatibility-only evidence로 계속 읽을 수 있으나 live writer가 생성하지 않으며 effective adoption, canonical live authority 또는 prospective transition state를 만들지 않는다. Authority-bound profile과 legacy profile은 exact key set으로 구분하고 혼합/부분 profile은 거부한다. Narrative migration과 broad guidance 정렬은 AC-008에 남긴다.

### 3. Exact evidence and authority validation

- 새 `src/specbound/iteration_qc.py`는 target identity를 exact `iqc-{numeric-id}-{positive-slice}-r1`로 제한하고 canonical path `.specbound/iteration-qc/req-{numeric-id}/iqc-{numeric-id}-{positive-slice}-r1.json`을 파생한다. AC-003 live writer는 exact Micro-SPEC당 verified canonical result 하나만 허용하므로 caller-selected revision, arbitrary output path, timestamp, policy selector, requirement/adoption/Micro-SPEC digest 또는 verdict를 받지 않는다.
- CLI는 exact target, implementation-result JSON path, evaluator-result JSON path, authority identity/action/context를 받는다. 두 input file은 canonical output이 아니라 read-only candidate evidence이며 repository 밖 path도 허용하되 bytes를 record에 복사하지 않고 validated closed fields만 writer가 파생한다.
- Implementation-result input은 exact top-level keys `schema_version`, `result_id`, `micro_spec`, `source_commit`, `actor`, `action_id`, `context_id`, `selected_acceptance_criteria`, `verification`, `verdict`를 가진다. `micro_spec`은 exact `{path,id,sha256}`, verification은 AC별 non-empty `{acceptance_criterion,command,result,exit_code}` 목록이며 verdict는 exact `pass`다. Writer는 whole-file canonical bytes의 SHA-256을 계산하여 record의 `implementation_result`에 result ID, digest 및 identity/source fields를 보존한다. 모든 selected AC에 최소 하나의 passing evidence가 있어야 하며 failed evidence, empty command, nonzero passed result, unknown AC, stale source commit 또는 candidate worktree bytes는 거부한다.
- Evaluation-result input은 exact top-level keys `schema_version`, `result_id`, `micro_spec`, `implementation_result`, `evaluator`, `action_id`, `context_id`, `selected_acceptance_criteria`, `verification_sha256`, `verdict`, `findings`를 가진다. `implementation_result`는 exact `{result_id,sha256}`, `verification_sha256`은 implementation result의 canonical ordered verification array bytes digest, verdict는 exact `pass`, findings는 빈 array여야 publication candidate가 된다. Writer는 whole-file canonical bytes의 SHA-256을 계산하여 record의 `evaluation_result`에 result ID/digest, exact implementation-result edge와 evaluator/action/context를 보존한다. Evaluator input은 authority identity나 canonical `verified` 결정을 지정하지 않는다.
- Writer는 pre-write clean tracked/untracked worktree, non-shallow SHA-1 repository와 `implementation_result.source_commit == HEAD`를 요구한다. Exact parent REQ/approval, Micro-SPEC/review `approved_for_implementation`, selected AC set, exact `iteration_qc` effective adoption, policy digest/current authority, evidence/evaluator binding과 absent target을 모두 fail-before-write 검증한다.
- `check_effective_adoption`의 exact state는 requirement path/ID/revision/SHA와 transition `iteration_qc`가 일치해야 한다. DQC adoption, legacy manual list, generated projection, invalid/conflicting adoption 또는 unactivated broad scope는 IQC publication authority가 아니다.
- Implementation actor와 authority identity가 같은 self-QC, 그리고 implementation/evaluator/authority action ID 또는 context ID collision은 distinct stable blocker로 거부한다. Evaluator와 authority identity가 같더라도 action/context가 모두 다르면 허용한다. Agent role result, advisory PASS, CI status 또는 caller assertion은 allowlisted authority action을 대체하지 않는다.
- Writer는 exact Micro-SPEC numeric ID/slice에 authority-bound IQC record가 하나라도 이미 있으면 revision과 무관하게 `iteration_qc_already_exists`로 mutation 전에 거부한다. Live writer는 `r1`만 발행하고 rework/blocked evaluation은 canonical target을 만들지 않으므로 retry는 absent `r1`에 같은 exact inputs를 다시 검증한다. Validator는 동일 Micro-SPEC에 복수 authority-bound profile 또는 authority-bound `r2+`가 있으면 conflict로 모두 fail closed한다. Legacy compatibility-only record의 historical revision은 effective live result 선택에 참여하지 않으며 last-writer-wins를 사용하지 않는다.

### 4. Distinct writer and failure-atomic publication

- `src/specbound/cli.py`에 authority-bearing `specbound iteration-qc decide` command family를 추가하고 copied-fixture `issuance-request iteration-qc`와 parser/help/result에서 명확히 분리한다. Existing `issuance-request`의 read-only prevalidation 및 copied-fixture behavior는 변경하지 않는다.
- Mutation은 allowlisted iteration-QC target의 exact 새 leaf 하나에 한정한다. POSIX directory-relative no-follow traversal, exclusive create, full write, file fsync, directory fsync, final inode/digest check와 post-write full `specbound validate`를 적용한다.
- Writer가 exclusive-create 직후 확보한 `(st_dev, st_ino)`만 operation ownership으로 사용한다. Write/file-fsync/directory-fsync/final-read/post-validation failure에서 current leaf가 그 identity와 일치할 때만 제거하고 replacement winner, pre-existing target, source, Micro-SPEC, review, adoption, policy 및 다른 canonical root는 보존한다.
- POSIX `O_DIRECTORY|O_NOFOLLOW` 등 required primitive가 없거나 Git contract가 지원되지 않으면 mutation 전에 `unsupported_platform` 또는 specific Git blocker를 반환한다. Windows silent fallback은 구현하지 않는다.
- 성공 payload는 exact canonical target과 final SHA-256을 반환한다. 이 결과는 canonical IQC record publication evidence일 뿐 Delivery, Merge, Release 또는 broader activation authority가 아니다.

## QC exit rule

이 slice는 AC-003 implementation-result가 exact canonical `approved_for_implementation` review binding 아래 구현되고, independent IQC authority policy, exact adopted/reviewed/evidence binding, self-QC 및 evaluator/authority separation, distinct failure-atomic live writer, complete positive/negative/fault matrix, source/full/root/docs, installed-wheel parity와 exact-head Ubuntu Python 3.11/3.12를 모두 통과한 뒤에만 Bootstrap formal Iteration-QC advisory 평가를 요청할 수 있다. ## Rollback and containment

- Implementation defect가 발견되면 `iteration-qc decide` parser/writer와 authority-bound profile acceptance를 함께 fail-closed disabled 상태로 되돌리고 legacy unscoped validation compatibility를 보존한다. Policy/config/template/schema/package mirror를 함께 rollback하여 writer와 validator가 다른 authority contract를 사용하지 않게 한다.
- Writer rollback은 exclusive-create가 반환한 operation-owned exact leaf만 제거하며 pre-existing/replacement target, implementation/evaluator evidence, source, REQ/approval, Micro-SPEC/review, adoption 및 다른 canonical root를 삭제하지 않는다.
- Approved parent REQ/approval, `ms-0005-001`/review, transition policy, existing Bootstrap evidence와 live Hermes profile은 immutable containment boundary다.
- 실제 live IQC/adoption/canary/activation/DQC record가 생성되거나 exception ledger/matrix가 변경되면 즉시 중단하고 bytes, Git state와 command evidence를 보존한다. 그것은 이 Micro-SPEC의 정상 rollback 권한으로 삭제할 수 없는 authority incident다.
