# MS-0001-001 — Canonical artifact topology and version-one schema envelope

## 1. Objective

Satisfy **REQ-0001-r1 AC-001** by making the three artifact families separately recognizable and fail-closed: human-readable Markdown Micro-SPECs, machine-readable iteration-QC JSON, and machine-readable delivery-QC JSON. This slice establishes only their exact paths, positive numeric identifiers/revisions, and `schema_version: 1` envelope.

## 2. Selected scope

- Add configuration and validator constants for exactly:
  - `.specbound/micro-specs/req-<id>/ms-<id>-<slice>.md`;
  - `.specbound/iteration-qc/req-<id>/iqc-<id>-<slice>-r<revision>.json`; and
  - `.specbound/delivery-qc/req-<id>/dqc-<id>-r<revision>.json`.
- Validate that every discovered record is in its exact family topology, has a positive decimal identifier component, and contains `schema_version: 1` in its required representation.
- Reject malformed JSON/frontmatter, noncanonical descendants, and any symlinked root, directory, or artifact component.
- Add templates, schema envelopes, copied-fixture tests, README/governance/skill updates, and CLI context output that use the same canonical contract.

## 3. Non-goals and boundary

- Do not implement Micro-SPEC parent-REQ/digest/selected-AC completeness (AC-002).
- Do not implement iteration-QC evidence, verdict, or coverage semantics (AC-003), delivery aggregation/authority (AC-004), or adoption behavior (AC-005).
- Do not issue, overwrite, migrate, canonicalize, or relabel manual-bootstrap records, including existing `req-0002` records.
- Do not change Discovery, REQ, approval, rejection, merge, delivery, release, or live Hermes-profile behavior.
- Preserve unrelated existing working-tree changes; only the files attributable to AC-001 may be changed.

## 4. Baseline and design decision

The baseline is `.venv/bin/python -m pytest -q` and `.venv/bin/python -m specbound.cli validate` passing before this slice, while the validator ignores all three new families. The existing safe-path helpers and root enumeration pattern are reused; each new family has a distinct root and filename regular expression so planning Markdown cannot be accepted as QC/control JSON.

## 5. Acceptance checks

1. `preflight` rejects a missing, unsafe, or wrong configuration contract for any of the three families.
2. A copied valid fixture containing one schema-version-one instance of each family passes `validate`.
3. Wrong nesting, mismatched directory/filename ID, zero/non-decimal slice/revision, missing/wrong schema version, malformed JSON/frontmatter, and symlinked family paths produce deterministic blockers.
4. Templates, JSON schemas, configuration, CLI context, README/governance, and repository-local skill all state the same exact topology and explicitly preserve the non-authority boundary.
