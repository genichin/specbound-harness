# REQ: Lifecycle agent contracts and one-shot delegated execution r1

> **Lifecycle boundary:** 이 artifact의 lifecycle state는 frontmatter와 이에 대응하는 content-addressed decision record로만 결정된다. `draft` 발급은 review, rejection, approval 또는 implementation 권한이 아니다.
>
> **Review handoff:** 이 draft는 먼저 `specbound req check-readiness req-0004-r1`을 통과한 뒤에만 `specbound req to-in-review req-0004-r1`로 제출한다. 이 transition은 exact draft/reviewed digest를 가진 non-authorizing review-submission record만 만들며, review decision, rejection, reconsideration, approval, implementation, merge, delivery 및 release는 각각 별도 authority action이다.

## 목표 (Goal)

SpecBound lifecycle의 7개 논리적 LLM 역할을 provider-neutral policy, 공통 structured result schema와 repository-backed skill로 정의하고, caller가 명시한 lifecycle-eligible 역할 하나만 새 isolated context에서 실행하는 Hermes adapter를 제공한다. 역할별 최소 권한, exact artifact binding, producer/reviewer/QC/authority 분리, Risk 및 evidence applicability를 CLI/CI가 fail-closed하게 검증하며 어떤 agent verdict도 canonical lifecycle authority로 승격하지 않는다.

## Scope (범위)

- 정확히 7개 역할(`discovery-author`, `requirement-author`, `micro-spec-author`, `independent-reviewer`, `implementation`, `iteration-qc`, `delivery-qc`)의 provider-neutral machine-readable policy와 1:1 repository-backed `SKILL.md`.
- exact target path/ID/revision/SHA, 역할·execution·context identity, context provenance, changed paths, evidence applicability, structured verdict와 permitted next action을 표현하는 provider-neutral `agent-result` schema.
- 역할별 allowed/forbidden path, tool category, mutation class, input/output, lifecycle claim 및 current-state eligibility에 대한 deterministic validation.
- Artifact Risk, task floor, Effective Task Risk, evidence `provided/not_applicable` 규칙과 기존 transition-specific authority selector의 분리.
- caller-selected role 하나를 하나의 adapter-configured model alias와 새 isolated context로 실행하고 공통 result로 변환하는 최소 Hermes adapter.
- positive/negative copied-fixture, schema/CLI/adapter test, 지원 CI, repository guidance 및 기존 lifecycle regression 검증.

## Non-goals (비목표)

- 다음 역할의 자동 선택, lifecycle chain 자동 진행, retry/loop/scheduler, 여러 역할 동시 orchestration 또는 자동 status transition.
- 7개 persistent Hermes profile, multi-model routing, provider/vendor/model ID를 core policy에 고정하거나 live Hermes profile/config를 변경하는 작업.
- agent가 confirmation, review decision, rejection, reconsideration, approval, Delivery decision 또는 그 canonical authority record를 대신 발행하는 기능.
- production/external mutation, automatic Merge/Release Agent/Bot, cross-repository coordination, cryptographic agent identity 또는 external policy engine.
- 기존 confirmed/approved artifact나 authority record의 in-place 수정, 기존 수동 adopter workflow의 강제 migration, implementation·merge·delivery·release 권한 부여.

## Acceptance criteria

> **AC completion contract:** 각 AC의 직접 evidence는 isolated/copy fixture 또는 repository-local deterministic check에서 수집한다. 같은 completion group은 group 전체가 검증되기 전 implementation-ready claim을 만들지 않는다.

### AC-001 — 정확히 7개 provider-neutral 역할과 최소 권한 policy

- `observable_success`: repository-owned `agent-roles` policy가 정확히 7개 stable role ID를 정의하고 각 역할의 required input, allowed path/tool category, mutation class, output kind, forbidden action/claim 및 lifecycle eligibility를 machine-readable하게 제공한다. Discovery/REQ/Micro-SPEC author는 자신의 candidate family만, Independent Reviewer는 read-only, Implementation은 reviewed Micro-SPEC이 허용한 source 범위만, IQC/DQC는 자신의 candidate evidence family만 변경할 수 있다.
- `required_preconditions`: confirmed `dcy-0004-r1`, 기존 canonical lifecycle roots와 transition policy, safe repository-relative path contract.
- `mutation_boundary`: policy 구현은 repository-owned policy/schema/template/test/guidance만 변경하며 기존 canonical lifecycle artifact, decision record와 live Hermes profile을 변경하지 않는다.
- `negative_behavior`: 누락·중복·unknown role, absolute/traversal/symlink escape path, 역할에 금지된 tool/mutation/output/authority claim 또는 current-state-ineligible role은 실행·candidate publication 전에 distinct structured blocker로 거부된다.
- `direct_evidence`: policy schema positive fixture 7개와 role별 forbidden path/tool/mutation/claim negative fixture, duplicate/missing/unknown role fixture, safe-path assertions 및 `specbound validate`.
- `dependencies`: none
- `completion_group`: CG-1: core role policy and agent-result schema must be reviewed together
- `candidate_micro_spec`: ms-0004-001
- `non_goals`: agent를 human authority, CLI/CI enforcement authority 또는 Merge/Release executor로 정의하지 않는다.

- `negative_behavior`: missing/orphan/duplicate skill, policy와 다른 role ID, 더 넓은 path/tool/mutation, self-review/self-approval 또는 authority claim을 포함한 skill은 alignment validation에서 거부된다.

- `required_preconditions`: reviewed `ms-0004-001`의 role/result contract, confirmed parent의 `high` risk, low/medium/high ordering, task-kind floor와 mutation class definitions.
- `mutation_boundary`: risk/evidence 계산은 read-only이고 authority record나 target risk를 자동 변경하지 않는다.
- `negative_behavior`: risk 하향, unknown task/mutation class, missing evidence, blanket/empty `not_applicable`, task risk를 authority selector로 사용, high repository mutation에서 지원 CI·negative/rollback evidence 누락 또는 external/production mutation 요청은 `blocked`된다.
